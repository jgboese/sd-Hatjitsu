# Dependency Update PR Comment

## What it does

1. **Check the current state**
   - `git status` and the files changed on this branch (`git diff master...HEAD --stat`)
   - Confirm a PR exists for this branch (`gh pr view`)
   - Confirm `package.json` / `yarn.lock` changed, and list each package whose version changed (old → new)
   - For each package: read its changelog / release notes for the versions in between (`yarn npm info <pkg>`, the GitHub releases page)
   - Find where it is used (`git grep`, `yarn why <pkg>`) and whether the update requires code changes
   - Check for security implications (advisories fixed or introduced, new install scripts, new transitive dependencies, maintainer changes)
   - If the update touches socket.io, express, or anything the client relies on, note whether the client/server protocol is affected

2. **Write the PR comment** in English, covering the update's changes

3. **Post the comment**
   - Add it to the PR with `gh pr comment`
   - State that it was generated by Claude Code

## Comment structure

- **Impact**: list of affected files
- **Code changes needed**: whether changes are required, where, and a summary of what
- **Security risk**: whether there is any risk, with a summary
- **Recommended action**: what to do next (merge, merge after running `yarn e2e`, hold, etc.)

## Usage

```
/check-package-update
```

## Prerequisites

- GitHub CLI installed and authenticated
- Run on the branch of the dependency-update PR
- Use yarn, not npm

## Output

- URL of the posted comment
- Any warnings or errors
